# Known departures

Places where the repo does not yet meet the target set by the [Effect skill](../.agents/skills/effect/SKILL.md). They are here so nobody copies them, and so a change that passes through one knows what to move it to.

## Runtimes and edges

- **What the writer still does outside its layer graph.** The session is built after boot, in a scope `ReleaseForRestore` can close, so the per-port `InventoryStore` server receives it, with the session's one `CommandAdmission`, through `Layer.succeedContext(session)` (`apps/desktop/electron/replica-worker-handlers.ts:233`), and `ReleaseForRestore` takes that admission's exclusive turn (`:313`). The live socket's `accessToken` option is a Promise callback (`packages/sync/src/live-socket.ts:35`), so the worker re-enters through `FiberSet.makeRuntimePromise` (`replica-worker-handlers.ts:114,121`). The infra RPCs of `ReplicaWorkerRpcs` and `ReplicaReaderRpcs` still fail with `ReplicaWorkerFailure { message }` (`apps/desktop/electron/replica-rpc.ts:145-198`), and `workerFailure` flattens engine errors to that message (`replica-worker-handlers.ts:64`); the renderer-facing `InventoryStore` carries the typed `CommandFailure`. Target: `OwnedLiveHost.accessToken` takes an `Effect`; the infra RPC errors become a tagged union.
- **Renderer RPC clients outlive their atom runtime by 10 s.** `outlivingItsRuntime` in `packages/inventory-react/src/services.ts` builds each `RpcClient` in a scope it closes on a detached, delayed fiber. Measured three times, the last on the per-catalog build: when a catalog's ports atom changes, `Atom.runtime` disposes the old layer scope before dependants detach, and the `RpcClient` scope finalizer interrupts every in-flight entry synchronously. Without the linger a mounted read shows `Failure(interrupt)` twice before the rebuilt runtime answers, the console reports errors on removal, and an in-flight command reports an interrupt where `generationMoved` should report `ReplicaUnavailable { reason: "restarting" }`. With it the read goes `waiting` to `Success`. The linger serves worker restarts inside one workspace, not workspace switches. The cost is one read re-sent on the dead port. Target: drop it when `Atom.runtime` detaches dependants before closing the previous scope, or when `AtomRpc` exposes a client lifetime.
- **`host/electron.ts` creates its `PubSub` and `SubscriptionRef` with `Effect.runSync`.** `apps/desktop/src/host/electron.ts:119,145`, and `:149` sets the ref the same way, outside the shell `ManagedRuntime` (`:94`) that is the renderer's edge. Target: build them in the shell layer, or take them from the runtime.
- **`leaveRegistryBatch` works around the registry.** `apps/desktop/src/session/workspace-session.ts:161` suspends a microtask so `flush` (`flushSync`) runs after the `AtomRegistry` batch that is running `commitWorkspaceChange` has ended. `AtomRegistry` has no after-batch hook that it could use instead. Target: that hook, or a registry API that runs a function outside the batch.
- **Session ports are seeded by `registry.set` after the router exists.** `startWorkspaceSession` (`apps/desktop/src/session/workspace-session.ts:150`, called from `apps/desktop/src/mount-app.tsx:37` once `getRouter` has returned) sets `workspaceSessionPorts` (`:155`), which `sessionRuntime` (`:109`) turns into a layer, because `invalidate` needs the router. A session that is not started fails with `WorkspaceSessionPortsMissing`. Target: the ports as a `Layer` the router and registry both take, so a missing port is a build error.
- **A closed worker port fails the run with a `WorkerReceiveError`.** `closed()` in `apps/desktop/electron/message-port-main-runner.ts:13` is raised from the port's `close` handler (`:48-49`). The electron smoke reports it as a `MessagePortMain closed` ERROR log at `ApplyRestore`, where closing the port is expected; not reproduced here. Target: treat a close that follows a requested release as normal shutdown.
- **The renderer configures no logger or tracer.** The atom runtimes share the default `Atom.runtime` factory, so one memoMap per registry (`packages/inventory-react/src/services.ts`, `preferences.ts`, `apps/desktop/src/session/workspace-session.ts`). The shell host's `ManagedRuntime` (`apps/desktop/src/host/electron.ts:94`) builds only the shell RPC client and stays separate. Nothing else exists to share. Target: when a renderer logger or tracer is added, provide it with `Atom.runtime.addGlobalLayer` and as a layer of the host runtime.
- **`Effect.runPromise` in React code.** `apps/desktop/src/lib/inventory/preload.ts:19`. Target: an atom or the host facade.
- **Command atoms are non-concurrent per command.** A second call of the same command atom interrupts the first client fiber: `Atom.fn` without `concurrent: true` keeps only the latest argument (`makeResultFn` in `node_modules/effect/dist/reactivity/Atom.js`), and `concurrent: true` would join every running fiber and return the first result, which misattributes outcomes. No caller invokes one command twice at once today.
- **`runtime.fn` re-runs its last argument when its runtime rebuilds.** Read from `makeResultFn` in `node_modules/effect/dist/reactivity/Atom.js`, not verified by a test. A port-fed runtime (`Reads`, `Store`, `Insights` after a port change) must not host write commands.

- **Three layer spellings and two interface suffixes.** `X.layer`, `layerX` (`packages/client-db/src/replica/node-sync.ts:33`, `packages/sync/src/session.ts:89`, `packages/workspace/src/session-http.ts:552`, `apps/desktop/electron/desktop-rpcs.ts:28`) and `XLive` (`apps/desktop/electron/host.ts:54`, `apps/server/infra.ts:28`); `OrgAuthorityApi` (`apps/server/src/authority/facade.ts:59`) and `OrgHubContract`, `OrgAuthorityContract` (`apps/server/api.ts:10,33`). `sessionEndingCodes` stays `ReadonlySet<string>` (`packages/auth/src/http-errors.ts:116`) until `packages/workspace/src/session-http.ts:308` passes a typed `AuthErrorCode`, and `AuthRefusal` reasons such as `"RateLimited.request"` (`apps/auth/src/failures.ts:129`) are still dotted. Target: the naming table in [services and layers](../.agents/skills/effect/references/SERVICES_LAYERS.md), with the interface inline.
- **The analytics store runs synchronous SQL behind a per-method Effect.** `packages/client-db/src/analytics/store.ts` builds its methods over `node:sqlite` and Drizzle's synchronous driver, and `guardAll` (`packages/client-db/src/analytics/errors.ts`) lifts each method to `Effect.try` with an `AnalyticsFailure`. It runs in the dedicated analytics worker thread, not Electron main. Measured in single runs on a 1444-product replica, a full refresh takes about 0.4 to 0.7 s, store calls are about 30% of that, and the longest single synchronous call is about 42 ms. `@effect/sql-sqlite-node` drives the same `node:sqlite` engine, so a `SqlClient` layer would not change engine cost; it would add a span per statement and need a reshaped `SummaryReader`. Accepted edge unless a 10x-shop measurement shows blocks above about 100 ms; if it does, split the long writes into smaller transactions with `Effect.yieldNow` rather than switching clients.
- **Unnamed service methods.** `packages/workspace/src/session-http.ts` (5 `Effect.gen`) and `session-broker.ts` (2), `packages/inventory-react/src/services.ts:228,274`, the Electron main files `updater.ts`, `replica-supervisor.ts`, `shell-handlers.ts` and `licence/service.ts`, and the internal steps of `packages/sync/src/engine.ts` (`:185,208,388,398,407,437`) use `Effect.gen` where `Effect.fn("Service.method")` belongs, so their traces have no spans. `packages/inventory-react/src/workspace.ts` and the session module are named; the one `Effect.gen` left in the renderer is the `workspaceSessionFeed` body (`apps/desktop/src/session/workspace-session.ts:229`).

## Needs the user's decision

These are architecture choices, not refactors. Raise them; do not start them inside another task.

- **Electron main as one layer graph.** `apps/desktop/electron/main.ts` is an async bootstrap with module-level handles and a broker per concern. The target shape is Electron APIs wrapped as services and one program under `NodeRuntime.runMain`. It changes startup order, so cold start must be measured before and after.
- **`DateTime` on the wire.** Timestamps are epoch-millisecond numbers end to end. Changing that is a protocol change.
- **`effect/eventlog`: evaluated 2026-10-04, rejected.** An event log replicates accepted entries; it has no way for the authority to refuse a command, and stock refusal with a receipt is the sync contract. Do not reopen without a new fact.
- **`@alchemy.run/domain`: evaluated 2026-10-24, rejected as the host.** Its commands, refusals, decide/evolve split and views are the model. Its Durable Object event log would replace the replica and the receipt. The same ideas are pure `Result` decisions in `@store/contracts`, recorded in [the domain ADR](adr/0001-domain-decisions-stay-in-effect.md). Do not reopen without a new fact about refusals and receipts.
- **`Workflow`/`Activity` and `PersistedQueue`: evaluated 2026-10-04, rejected.** The 2026-10-04 [repo audit](effect-audit-2026-10-04.md) mapped `Workflow`/`Activity` on `Cluster.SingleRunner` to catalog publishing. On a single runner it adds a runner, storage tables and replay rules to a flow whose steps are already idempotent and resumable from the staged file, so it is a net addition. `PersistedQueue` for scan drafts duplicates `draft.json`. The IndexedDB query executor the audit listed was deleted with the browser replica.

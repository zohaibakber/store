# Known departures

Places where the repo does not yet meet the target set by the [Effect skill](../.agents/skills/effect/SKILL.md). They are here so nobody copies them, and so a change that passes through one knows what to move it to.

- Entries come from a source survey on 2026-10-03. None was reproduced at runtime, so read the code before acting on one.
- Fix a departure when your task already changes that code. Otherwise leave it and say you saw it.
- Delete an entry in the change that fixes it. Add one when you find a new departure.

## Runtimes and edges

- **What the writer still does outside its layer graph.** The session is built after boot, in a scope `ReleaseForRestore` can close, so the per-port `InventoryStore` server receives it, with the session's one `CommandAdmission`, through `Layer.succeedContext(session)` (`apps/desktop/electron/replica-worker-handlers.ts:233`), and `ReleaseForRestore` takes that admission's exclusive turn (`:313`). The live socket's `accessToken` option is a Promise callback (`packages/sync/src/live-socket.ts:35`), so the worker re-enters through `FiberSet.makeRuntimePromise` (`replica-worker-handlers.ts:114,121`). The infra RPCs of `ReplicaWorkerRpcs` and `ReplicaReaderRpcs` still fail with `ReplicaWorkerFailure { message }` (`apps/desktop/electron/replica-rpc.ts:123-185`), and `workerFailure` flattens engine errors to that message (`replica-worker-handlers.ts:64`); the renderer-facing `InventoryStore` carries the typed `CommandFailure`. Target: `OwnedLiveHost.accessToken` takes an `Effect`; the infra RPC errors become a tagged union.
- **Renderer RPC clients outlive their atom runtime by 10 s.** `outlivingItsRuntime` in `packages/inventory-react/src/services.ts` builds each `Reads`, `Store` and `Insights` `RpcClient` (the `Desktop` client does not use it) in a scope it closes on a detached, delayed fiber. Measured three times, the last on the per-catalog build: when a catalog's ports atom changes, `Atom.runtime` disposes the old layer scope before dependants detach, and the `RpcClient` scope finalizer interrupts every in-flight entry synchronously. Without the linger a mounted read shows `Failure(interrupt)` twice before the rebuilt runtime answers, the console reports errors on removal, and an in-flight command reports an interrupt where `generationMoved` should report `ReplicaUnavailable { reason: "restarting" }`. With it the read goes `waiting` to `Success`. The linger serves worker restarts inside one workspace, not workspace switches. The cost is one read re-sent on the dead port. Target: drop it when `Atom.runtime` detaches dependants before closing the previous scope, or when `AtomRpc` exposes a client lifetime.
- **`host/electron.ts` creates its `PubSub` and `SubscriptionRef` with `Effect.runSync`.** `apps/desktop/src/host/electron.ts:126,152`, and `:156` sets the ref the same way, outside the shell `ManagedRuntime` (`:101`) that is the renderer's edge. Target: build them in the shell layer, or take them from the runtime.
- **`leaveRegistryBatch` works around the registry.** `apps/desktop/src/session/workspace-session.ts:161` suspends a microtask so `flush` (`flushSync`) runs after the `AtomRegistry` batch that is running `commitWorkspaceChange` has ended. `AtomRegistry` has no after-batch hook that it could use instead. Target: that hook, or a registry API that runs a function outside the batch.
- **Session ports are seeded by `registry.set` after the router exists.** `startWorkspaceSession` (`apps/desktop/src/session/workspace-session.ts:150`, called from `apps/desktop/src/mount-app.tsx:37` once `getRouter` has returned) sets `workspaceSessionPorts` (`:155`), which `sessionRuntime` (`:109`) turns into a layer, because `invalidate` needs the router. A session that is not started fails with `WorkspaceSessionPortsMissing`. Target: the ports as a `Layer` the router and registry both take, so a missing port is a build error.
- **Shell-port grant can race a navigation.** `makeShellPort` (`apps/desktop/electron/shell-port.ts:50`) bumps a document counter only on `did-start-navigation`, so an old document that requests a port before it unloads could take the grant meant for the new page. Not reproduced. Target: key the grant on the requesting frame's token and document, not on a counter the navigation event advances.
- **Renderer publish ids are plain strings.** `PublishTarget` in `apps/desktop/src/lib/local-publish.ts:25` and `publish`/`discard` in `apps/desktop/src/host/workspace-publish.ts:29` carry `string`, and the bridge decodes them to `OrganizationId` at the renderer edge (`apps/desktop/src/host/electron.ts:244-256`). Target: `OrganizationId` from the session onward.
- **`WorkspaceRefused` has no renderer copy.** It is not in the `BridgeFailure` union (`apps/desktop/src/host/index.ts:91`), so a refused `ReplicaClose` or `ReplicaRetry` reaches `bridgeSurface` (`apps/desktop/src/lib/errors.ts:13`) as an unknown failure and shows the generic message. Target: add it to the union and the exhaustive map.
- **`WorkspaceOpenFailed` is squashed and rebuilt from text.** `apps/desktop/src/host/electron.ts:107` throws `Cause.squash` of the exit, and `catalogOpenRefused` (`packages/inventory-react/src/errors.ts:60`) rebuilds a `CatalogOpenFailure` from `cause.message`, called from `apps/desktop/src/lib/inventory/host-electron.ts:50`. `no-error-message-from-cause` only matches a bare `instanceof Error ? x.message`, so it does not see this. Target: the bridge keeps the typed failure and the catalog open maps its `reason` instead of its text.
- **`DesktopAuth` is not in the target form.** The snapshot is a `MutableRef` (`apps/desktop/electron/auth.ts:136`), the session-broker hooks are optional (`packages/workspace/src/session-broker.ts:22`), and `Workspace.RequestError` carries `status: 0` and string codes (`packages/workspace/src/session-http.ts:119,152`). Target: a `SubscriptionRef` snapshot, required hooks, and a closed code union with a transport variant instead of status 0.
- **A closed worker port fails the run with a `WorkerReceiveError`.** `closed()` in `apps/desktop/electron/message-port-main-runner.ts:13` is raised from the port's `close` handler (`:48-50`). The electron smoke reports it as a `MessagePortMain closed` ERROR log at `ApplyRestore`, where closing the port is expected; not reproduced here. Target: treat a close that follows a requested release as normal shutdown.
- **The renderer configures no logger or tracer.** The atom runtimes share the default `Atom.runtime` factory, so one memoMap per registry (`packages/inventory-react/src/services.ts`, `preferences.ts`, `apps/desktop/src/session/workspace-session.ts`). The shell host's `ManagedRuntime` (`apps/desktop/src/host/electron.ts:101`) builds only the shell RPC client and stays separate. Nothing else exists to share. Target: when a renderer logger or tracer is added, provide it with `Atom.runtime.addGlobalLayer` and as a layer of the host runtime.
- **`Effect.runPromise` in React code.** `apps/desktop/src/lib/inventory/preload.ts:19`. Target: an atom or the host facade.
- **Command atoms are non-concurrent per command.** A second call of the same command atom interrupts the first client fiber: `Atom.fn` without `concurrent: true` keeps only the latest argument (`makeResultFn` in `node_modules/effect/dist/reactivity/Atom.js`), and `concurrent: true` would join every running fiber and return the first result, which misattributes outcomes. No caller invokes one command twice at once today.
- **`runtime.fn` re-runs its last argument when its runtime rebuilds.** Read from `makeResultFn` in `node_modules/effect/dist/reactivity/Atom.js`, not verified by a test. A port-fed runtime (`Reads`, `Store`, `Insights` and `Desktop` after a port change) must not host write commands. `Desktop` hosts `EnterLicence` (`enterLicence` in `packages/inventory-react/src/commands.ts:130`), accepted: the same text sent again is refused as `notNewer` by `LicenceService.enter` (`apps/desktop/electron/licence/service.ts:158-164`, reached through `sessionLicence` in `apps/desktop/electron/open-workspaces.ts:253`) and changes nothing, and the old runtime followed the latest port in the same way.

## Services and layers

- **`RuntimeContext` captured at layer build in `apps/server`.** `WebSearch` and `PageImages` in `packages/services/src/global-search/service.ts:39,45` have `R = never`, so `AiGateway` (`apps/server/src/ai/gateway.ts:34`) captures the worker `RuntimeContext` at layer build through `workerRuntimeServices` (`apps/server/src/runtime/isolate.ts:22`). `OrgAuthorities` and `OrgHubs` (`apps/server/src/inventory/organization-authority.ts:80`, `apps/server/src/live/org-hubs.ts:10`) are the deliberate layerless bridges from the Alchemy namespaces. Target: the services take `RuntimeContext` in `R` and the gateway reads the request's context.
- **Three layer spellings and two interface suffixes.** `X.layer`, `layerX` (`packages/client-db/src/replica/node-sync.ts:33`, `packages/sync/src/session.ts:89`, `packages/workspace/src/session-http.ts:555`, `apps/desktop/electron/desktop-rpcs.ts:28`) and `XLive` (`apps/desktop/electron/host.ts:32,53`, `apps/server/infra.ts:27,34`); `OrgAuthorityApi` (`apps/server/src/authority/facade.ts:59`) and `OrgHubContract`, `OrgAuthorityContract` (`apps/server/api.ts:10,33`). `sessionEndingCodes` stays `ReadonlySet<string>` (`packages/auth/src/http-errors.ts:116`) until `packages/workspace/src/session-http.ts:311` passes a typed `AuthErrorCode`, and `AuthRefusal` reasons such as `"RateLimited.request"` (`apps/auth/src/failures.ts:129`) are still dotted. Target: the naming table in [services and layers](../.agents/skills/effect/references/SERVICES_LAYERS.md), with the interface inline.
- **The analytics store runs synchronous SQL behind a per-method Effect.** `packages/client-db/src/analytics/store.ts` builds its methods over `node:sqlite` and Drizzle's synchronous driver, and `guardAll` (`packages/client-db/src/analytics/errors.ts`) lifts each method to `Effect.try` with an `AnalyticsFailure`. It runs in the dedicated analytics worker thread, not Electron main. Measured in single runs on a 1444-product replica, a full refresh takes about 0.4 to 0.7 s, store calls are about 30% of that, and the longest single synchronous call is about 42 ms. `@effect/sql-sqlite-node` drives the same `node:sqlite` engine, so a `SqlClient` layer would not change engine cost; it would add a span per statement and need a reshaped `SummaryReader`. Accepted edge unless a 10x-shop measurement shows blocks above about 100 ms; if it does, split the long writes into smaller transactions with `Effect.yieldNow` rather than switching clients.
- **Unnamed service methods.** `packages/workspace/src/session-http.ts` (5 `Effect.gen`) and `session-broker.ts` (4), `packages/inventory-react/src/services.ts:237,283`, the Electron main files `updater.ts`, `replica-supervisor.ts`, `shell-handlers.ts` and `licence/service.ts`, and the internal steps of `packages/sync/src/engine.ts` (`:185,208,388,398,407,437`) use `Effect.gen` where `Effect.fn("Service.method")` belongs, so their traces have no spans. `packages/inventory-react/src/workspace.ts` and the session module are named; the one service-level `Effect.gen` left in the renderer is the `workspaceSessionFeed` body (`apps/desktop/src/session/workspace-session.ts:229`), beside a scoped body nested inside the named `LocalPublish.move` (`apps/desktop/src/lib/local-publish.ts:79`).

## Needs the user's decision

These are architecture choices, not refactors. Raise them; do not start them inside another task.

- **Electron main as one layer graph.** `apps/desktop/electron/main.ts` is an async bootstrap with module-level handles and a broker per concern. The target shape is Electron APIs wrapped as services and one program under `NodeRuntime.runMain`. It changes startup order, so cold start must be measured before and after.
- **`DateTime` on the wire.** Timestamps are epoch-millisecond numbers end to end. Changing that is a protocol change.
- **`effect/eventlog`: evaluated 2026-10-04, rejected.** An event log replicates accepted entries; it has no way for the authority to refuse a command, and stock refusal with a receipt is the sync contract. Do not reopen without a new fact.
- **`@alchemy.run/domain`: evaluated 2026-10-24, rejected as the host.** Its commands, refusals, decide/evolve split and views are the model. Its Durable Object event log would replace the replica and the receipt. The same ideas are pure `Result` decisions in `@store/contracts`, recorded in [the domain ADR](adr/0001-domain-decisions-stay-in-effect.md). Do not reopen without a new fact about refusals and receipts.
- **`Workflow`/`Activity` and `PersistedQueue`: evaluated 2026-10-04, rejected.** The 2026-10-04 [repo audit](effect-audit-2026-10-04.md) mapped `Workflow`/`Activity` on `Cluster.SingleRunner` to catalog publishing. On a single runner it adds a runner, storage tables and replay rules to a flow whose steps are already idempotent and resumable from the staged file, so it is a net addition. `PersistedQueue` for scan drafts duplicates `draft.json`. The IndexedDB query executor the audit listed was deleted with the browser replica.
- **Schema version gate.** `apps/server/src/authority/engine.ts:259` and `apps/server/src/authority/imports.ts:403` hard-code `replica.schemaVersion < 2` to decide that a replica is too old for purchasing writes. The number belongs to one place in `@store/contracts`, and whether older replicas are refused, upgraded or tolerated is a product call.
- **Vocabulary merge.** `CONTEXT.md` and `GLOSSARY.md` are still two files, and `GLOSSARY.md` still says "Catalogue" (`:9`) and "Shop" where the ruling of 2026-10-25 chose one glossary using "catalog" and "organization". Merge them and rename in code and copy in one change.
